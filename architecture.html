System Overview
Multi-layered forensic genomic analysis
Ghost Signature detects three distinct classes of synthetic virus DNA origin: known cloning vectors and expression constructs (Vector class), novel computationally-designed virus sequences with no database homology (Ghost class), and naturally-occurring virus sequences (Natural class). The core architectural philosophy is that no single detection method is sufficient — engineered virus sequences can evade any individual detector through mutation, codon substitution, or deliberate obfuscation.

Input Processing
FASTA parsing, cleaning, statistics
Accepted Format
Virus nucleotide sequences in FASTA format. Multiple sequences can be submitted in a single multi-record FASTA file. Each record is processed independently, generating a dedicated forensic report section per sequence.
Sequence Cleaning
All characters converted to uppercase. Any character not in the canonical nucleotide alphabet {A, T, G, C, N} is removed. Prevents downstream k-mer and statistical corruption.
Python def clean_sequence(seq): # Retain only {A, T, G, C, N} in uppercase return ''.join(c for c in seq.upper() if c in 'ATGCN')
Basic statistics computed after cleaning: sequence length (bp), GC content (%), and FASTA header metadata. Used for reporting and triggering reliability flags at later stages.
3
Primary Engine — AI Classifier
Multi-scale k-mer TF-IDF + dense bio features → calibrated Random Forest — the system's headline classifier
3.1 Feature Representation — Multi-Scale K-mer Tokenisation
The virus sequence is decomposed into overlapping k-mers at three scales simultaneously: k = 4, 6, and 8. Each k-mer is prefixed with its scale (k4_ATGC, k6_ATGCAT, k8_ATGCATGC) to prevent vocabulary collision across scales. All tokens are concatenated and transformed using TF-IDF vectorisation (max 100,000 features, sublinear TF), producing a sparse high-dimensional feature vector. A 23 bp sequence yields 54 multi-scale tokens vs only 16 with k = 8 alone — enabling reliable classification down to the minimum detectable length of 20 bp.
3.2 Chunking Strategy
Long input sequences are divided into 500 bp windows (CHUNK_SIZE = 500 bp). Each chunk is independently transformed and classified. The final probability vector is the arithmetic mean across all chunks, making the classifier length-agnostic. Fragments as short as 4 bp are retained — the minimum length for one 4-mer token. Sequences of 20 bp or more produce enough multi-scale tokens for meaningful classification; sequences below 20 bp are routed to BORDERLINE without AI/OOD scoring.
Python chunk_sequence(seq, chunk=500) → list of fragments ≥ 4 bp predict_probabilities(seq) → mean P(Natural), P(Vector), P(Ghost)
3.3 Calibrated Random Forest + Hybrid Feature Vector
A single regularised Random Forest (300 trees, min_samples_leaf=2, max_features="sqrt", class_weight="balanced_subsample", OOB scoring) wrapped in isotonic CalibratedClassifierCV for well-calibrated probabilities. This replaced the earlier StackingClassifier: on genome-grouped folds with only ~15–30 genomes per training fold, the stack's inner CV was unstable and 3× slower for no AUROC gain. The classifier consumes a hybrid feature vector, not k-mers alone:
TF-IDF k-mers
Multi-scale k=4,6,8 tokens, ngram(1,2), min_df=3, 100k features
Dense bio features
GC content, CpG rate, 3rd-codon-position GC (GC3), z-scored
Motif enrichment
Max Ghost-vs-background 6-mer fold-enrichment per sequence
OOD score (as feature)
The anomaly score is fed in as ONE input column — it informs the model but casts no vote downstream (see §4)
Leakage-free cross-validation. Honest performance is enforced by three controls inside every CV fold: (1) genome-grouped StratifiedGroupKFold — all windows of a genome stay in one fold (a hard leakage assertion runs each fold); (2) the TF-IDF vectoriser is fit on the training fold only (fitting it on the full set previously leaked validation IDF statistics); (3) SMOTE oversampling is applied inside the training fold only. This dropped the reported cross-genome AUROC from a leakage-inflated ~0.98 to an honest 0.638 ± 0.078.

4
OOD Anomaly Scorer — Passive Diagnostic
Unsupervised novelty detection — metadata tag only, zero voting power
No decision power. The OOD scorer is not a voting engine. An ablation showed the unsupervised anomaly score has an independent-test AUROC of just 0.248 — it flags natural evolutionary variance and stochastic mutation as "synthetic," which inverts the ranking. Fusing it with the AI classifier dragged the full system from 0.903 → 0.564. It is therefore removed from every score, weight, and verdict gate. It still executes and is surfaced only as passive metadata — raw_ood_score and an is_novel_sequence_warning flag — for human review and the forensic report. (It is also fed into the AI classifier as one input feature, §3.3, where the supervised model decides how much to trust it.)
Conceptual basis: A supervised classifier asks "which class?" — the OOD scorer asks "does this fall within the statistical distribution of any natural virus genome?" A useful diagnostic question, but on this corpus it is too noisy to drive verdicts on its own — hence its relegation to a passive tag.
4.2 Dual-Envelope Architecture
Two IsolationForest one-class models, each trained on 4-mer frequency vectors (256-dimensional, vocabulary-independent) from a different natural genome corpus. Using 4-mer frequency vectors rather than TF-IDF means novel synthetic k-mers never collapse to zero — every sequence produces a meaningful score regardless of vocabulary coverage.
Viral Envelope PRIMARY
Trained on ~90 natural viral genomes
Prokaryotic Envelope REFERENCE
E. coli / Salmonella — shown for interpretability
# Viral envelope is the operational OOD score OOD_score = viral_score # (prokaryotic shown in report, not combined) # Two-anchor linear calibration: natural anchor → 0, ghost anchor → 100 score = (raw - cal_mean) / (cal_high - cal_mean) × 100
Why viral-primary, not max? Natural viral sequences are anomalous to the prokaryotic detector by design — combining via MAX would inflate natural sequence scores and invert the ghost detection signal. The prokaryotic envelope is reported for interpretability but is not combined into the operational verdict.

Detection Engine 3 — Homology Screening
BLAST vs NCBI UniVec database
Database: UniVec
NCBI UniVec — a curated collection of sequences from common laboratory vectors, cloning adaptors, linkers, primers, and other synthetic DNA elements used in virus engineering. Specifically designed for vector contamination screening with thousands of entries.
Search Parameters
blastn with e-value 1e-5 — stringent enough to exclude spurious short alignments while remaining sensitive to genuine vector homology. CSV output format 10 with 12 fields.
Bash blastn -query mystery_virus.fasta \ -db univec_db \ -evalue 1e-5 \ -outfmt 10 \ -out blast_hits.csv

Direct Evidence — Highest Tier: BLAST homology is classified as direct evidence. A confirmed hit means the virus query shares sequence-level identity with a known laboratory construct — binary, verifiable, independently confirmable. A single hit with ≥95% identity is sufficient to trigger CONFIRMED LAB-ENGINEERED regardless of AI or OOD scores.
Absence of Evidence Caveat: No BLAST hits does not exclude engineering. Engineered virus sequences can evade BLAST through synonymous codon substitution, deliberate mutation, or entirely novel de novo design. This is the primary motivation for the AI and OOD engines.

6.2 Exact Match Detection
Each motif searched as an exact substring match. No mismatches permitted — intentionally conservative to eliminate false positives. Like BLAST, constitutes direct evidence (strongest individual signal).
6.3 De Novo k-mer Enrichment
Query k-mers compared against background corpus of natural virus sequences. Fold-enrichment computed as frequency ratio. Top N enriched k-mers reported. Fold-enrichment above 10x flagged as unusual for natural sequences.
fold_enrichment = freq_in_query / freq_in_background

Detection Engine 5 — Codon Optimisation Analysis
CAI and RSCU forensic metrics
Purpose: Codon optimisation redesigns a virus gene's DNA to use codons preferred by a specific host organism, dramatically increasing protein expression. The resulting sequence has no BLAST homology to the original gene but carries a detectable statistical signature in its synonymous codon usage pattern.
7.2 Codon Adaptation Index (CAI)
Measures how closely codon usage matches reference organism preferences. Computed as geometric mean of relative adaptiveness values.
CAI = exp( (1/N) × Σ ln(w_i) ) # w_i = ratio of codon usage to most frequent synonymous codon # Range: 0 to 1 # Natural viral: 0.4–0.6 | Optimised: > 0.65 (FLAGGED)
7.3 RSCU Bias Metric
RSCU measures deviation from equal usage of synonymous codons. Aggregated bias metric across all codons:
RSCU_i = observed / expected_count RSCU_bias = mean(|RSCU_i - 1.0|) across all codons # RSCU > 1.5 → preferred (RED) # RSCU < 0.5 → avoided (BLUE) # RSCU_bias > 0.45 → FLAGGED as optimised
7.4 RSCU Bar Chart Visualisation
Each codon rendered as a bar: RED (RSCU > 1.5, preferred), BLUE (RSCU < 0.5, avoided), GREY (neutral). Natural virus sequences show moderate distributed bars; optimised sequences show extreme red/blue bars with few grey.

8.1 Evidence Hierarchy

The calibrated Random Forest engineered-risk score drives the verdict. Model-dependent; OOD novelty is shown alongside as a passive tag, not combined.

Absence of signals reduces probability but does not exclude engineering.
8.2 Verdict Assignment Rules
The headline suspicion score is a cascade, not a weighted blend of engines: direct database/motif evidence is a deterministic override, otherwise the AI classifier probability is the score. OOD and the soft codon signal contribute nothing.
S_fused = 1.0 if (BLAST hit or motif hit) else P_engineered # AI classifier; OOD & codon excluded
Python — AI-driven verdict (OOD has no vote) if BLAST_hits > 0 or known_motifs detected: verdict = "CONFIRMED LAB-ENGINEERED" # hard DB/motif override elif seq_len < 20: # too short for the AI gate verdict = "BORDERLINE / REVIEW" # short-seq policy bypass elif AI_risk >= 60: # calibrated peak-F1 operating point verdict = "SUSPECTED ENGINEERED" # rgb(235, 125, 20) elif AI_risk >= 35: verdict = "BORDERLINE / REVIEW" # rgb(190, 155, 25) else: verdict = "LIKELY NATURAL" # rgb(25, 135, 85)
Why AI-driven, not AI-AND-OOD? The previous dual gate gave the OOD scorer veto power. Because OOD inverts the ranking (§4), that gate suppressed true positives without the specificity benefit it was assumed to provide — and the fused score collapsed to 0.564. The verdict now rides the AI classifier alone, with BLAST/motif as hard overrides. At the calibrated AI ≥ 60% operating point (peak-F1), this yields engineered recall ≈ 83% at a natural false-positive rate of ≈ 13–15% on the independent test set.

8.3 Signal Conflict Detection
The system actively detects and reports logical conflicts between engines:
AI-OOD Conflict
AI risk high but OOD score low. May be known vector type well-represented in OOD training.
Short Sequence Limitation
Below 50 bp — SHORT_FRAGMENT flag raised. Below 20 bp — AI/OOD gates bypassed; BLAST and motifs are primary evidence.
Convergent Evidence
Multiple independent engines agree — provides strong multi-signal confirmation.

P1 BLAST Coverage Map
Each BLAST hit rendered as a red rectangle spanning query coordinates. Full red coverage = entire virus sequence matches known vectors. Empty (grey) = no homology.
P2 GC Content Profile
Sliding window GC% profile. Window scales with sequence length (min 20 bp, max 100 bp). Unusual GC (<30% or >65%) or sharp discontinuities indicate compositional manipulation or insertion boundaries in the virus genome.
P3 AI Risk Profile
Per-window AI risk score plotted spatially. Dashed line at 40% marks alert threshold. Flat elevated profiles = whole-sequence anomaly. Localised spikes = specific inserted synthetic elements.
P4 Shannon Entropy Profile
Per-window sequence entropy: H = −Σ p_b × log₂(p_b). High entropy (~2.0) = high base diversity (expected natural). Low entropy = repetitive/low-complexity. Sharp drops identify tandem repeats or synthetic repeat elements.
9.2 K-mer Saliency Map
Identifies which specific positions most strongly drive the synthetic classification. Each k-mer assigned a saliency weight based on its contribution to the synthetic class prediction. Positive weights push toward synthetic; negative weights push toward natural. Provides single-position resolution for forensic investigators to identify specific virus subsequences of concern.
9.3 Signal Gap Plot
2D scatter: X = BLAST similarity %, Y = OOD score. Defines the "Ghost Novelty Zone" (top-left: high OOD + low BLAST) — engineered virus sequences that all existing BLAST-based tools would fail to detect. Primary visualisation of the system's novel detection capability.

Key Design Decisions and Their Rationale
Architectural justification for each major choice
What role does each engine play now?
The architecture is a cascade led by one strong engine, not a flat vote. The calibrated AI classifier produces the headline probability; BLAST homology and curated motif hits are hard deterministic overrides (definitive, falsifiable evidence). The OOD scorer and codon-bias analysis are diagnostic context — surfaced in the report, and (for OOD) fed to the classifier as an input feature — but given no direct vote. Each still covers a blind spot, yet only the reliable signals are allowed to decide.
Why is the OOD score viral-primary rather than a max across envelopes?
Natural viral sequences are anomalous to the prokaryotic envelope by design — taking a max across envelopes would label normal viruses as outliers and invert the signal. The viral envelope alone is the diagnostic OOD score; the prokaryotic envelope is reported for interpretability only. Since the OOD score no longer participates in any verdict, this choice now affects only the displayed novelty tag, not classification.
Why use TF-IDF rather than raw k-mer counts?
Raw k-mer counts are dominated by highly frequent k-mers that appear in both natural and synthetic virus sequences. TF-IDF suppresses uninformative common k-mers and amplifies discriminative rare k-mers specific to synthetic sequence classes, improving classifier precision in the high-dimensional feature space. The vocabulary is capped at 100,000 features to cover multi-scale k=4,6,8 tokens, with min_df=1 to retain rare synthetic k-mers that appear only in a few training sequences.
Why relegate the OOD scorer to a passive tag?
An ablation isolated each engine's contribution to the fused decision. The unsupervised OOD score reached an independent-test AUROC of only 0.248 — below chance — because it reads natural evolutionary variance as anomalous, inverting the Ghost/Natural ranking. Giving it any vote (fusion weight or verdict gate) dragged the full system from 0.903 down to 0.564. Removing it entirely and letting the calibrated Random Forest drive the verdict recovers the ~0.90 operating point. OOD is retained only as diagnostic metadata, and as one input feature the supervised model is free to down-weight.
Why a single calibrated Random Forest rather than a stacked ensemble?
The genome-grouped cross-validation leaves only ~15–30 genomes in each training fold. A StackingClassifier runs an inner CV on that tiny, grouped sample to fit its meta-learner — unstable and ~3× slower, for no measurable AUROC gain. A single Random Forest with out-of-bag scoring and balanced_subsample weighting is more stable on small folds, and isotonic CalibratedClassifierCV supplies the probability calibration the meta-learner used to provide.
Why separate verdict rules rather than a single threshold?
The two-tier system (direct evidence → statistical evidence) reflects the epistemological difference between evidence types. A BLAST hit is falsifiable and independently verifiable. A high AI risk score is a probabilistic inference. Treating them with the same threshold logic would either under-weight definitive evidence or over-weight probabilistic inference. The rule-based verdict preserves this distinction explicitly.
